# Profile artwork

Every animated panel on the profile is a hand-built SVG generated by `gen_svgs.py`.
Nothing is fetched from a third-party service at view time.

```bash
python3 scripts/gen_svgs.py   # rebuilds everything in assets/
```

| File | What it shows |
|---|---|
| `assets/header.svg` | Name reveal, rotating tagline, legacy data flowing into one org |
| `assets/stats.svg` | Count-up stat cards with filling rings |
| `assets/timeline.svg` | Career timeline that draws itself |
| `assets/pebble.svg` | Pebble Time 2 cycling through Dicey Depths, Round 2 through the other apps |
| `assets/footer.svg` | Sign-off with moving waves |

The Pebble panel embeds the apps' store stills from `~/Projects/pebble` (Dicey Depths'
`store/screenshots/`, the rest from each app's `store/`), so regenerate it after a new store set.

The animated app cards in `assets/showcase/` are not built here. They are the `*_720.gif`
files from `~/Projects/pebble/showcase/build_showcase.py`, which puts each app's store
preview GIFs into its store banner and re-encodes the result with ffmpeg so it stays small.
Copy them in without the `_720` suffix. Black Parade doesn't animate, so its card is its store
`banner_720x320.png`, copied as `black-parade.png`. The stills under `assets/dicey/` are copies
of Dicey Depths' `store/screenshots/emery/` PNGs.

The Flood Control and Flood Backups cards in `assets/flood/` are screenshots from a sandbox.
Before each capture, people's names and anything specific to the org (its own objects, tabs and
branding) were blurred or hidden in the page itself. The merge example uses test records. Each shot is then framed on the
profile's navy with a caption, as 1200x760 JPEGs. Retake them the same way: never commit a
capture that shows real people's data.

`assets/login-frame/showcase.gif` is a copy of `docs/media/showcase.gif` from
[salesforce-login-frame](https://github.com/nathanm95/salesforce-login-frame), where
`npm run showcase` films it on a real login page. Copy it again after a new release.

The snake in the GitHub activity section is drawn by `.github/workflows/snake.yml`
([Platane/snk](https://github.com/Platane/snk)) every night and on every push to `main`. It
publishes `github-snake.svg` and `github-snake-dark.svg` to the `output` branch, which the README
loads from raw.githubusercontent.com. The snake only eats contributions GitHub counts, so commits
need an email on the account, and private repos need "Include private contributions" turned on.
